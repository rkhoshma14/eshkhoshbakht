# ربات مدیریت اشتراک (eshkhoshbakht)

ربات تلگرامی برای مدیریت لینک‌های اشتراک VPN/پروکسی.  
چند لینک اشتراک می‌دهی، با اسم و یادداشت ذخیره می‌شوند، کانفیگ‌ها پارس می‌شوند، پینگ می‌گیرند، و می‌توانی اشتراک‌های سفارشی روی دامنه خودت (Railway) بسازی.

پشتیبانی از: `vmess` · `vless` · `trojan` · `ss` و هر فرمتی که بعد از `#` دارای remark باشد.

---

## امکانات

### مدیریت اشتراک‌های اصلی
| قابلیت | توضیح |
|--------|--------|
| ➕ افزودن اشتراک | لینک ساب → اسم → یادداشت اختیاری |
| 📋 لیست اشتراک‌ها | صفحه‌بندی، باز کردن جزئیات |
| 🔄 بروزرسانی | دوباره fetch از لینک اصلی |
| 📝 یادداشت | افزودن / پاک کردن یادداشت |
| 📤 خروجی اشتراک | خروجی base64 همه کانفیگ‌ها |
| 📶 پینگ | تست TCP موازی همه کانفیگ‌ها |
| 🧹 حذف کانفیگ‌های مرده | پینگ → لیست مرده‌ها → تأیید حذف گروهی |
| ✏️ رنیم تکی | انتخاب یک کانفیگ و تغییر remark |
| 🗑 حذف اشتراک | با تأیید |

### ساخت اشتراک سفارشی (روی دامنه Railway)
از داخل هر اشتراک یا از منوی اصلی:

1. **تک‌منبع** — دکمه «🛠 ساخت اشتراک سفارشی» داخل یک اشتراک  
2. **چندمنبع** — دکمه «🌐 ساخت از چند منبع» در منوی اصلی  

جریان کار:
1. انتخاب کانفیگ‌ها (تیک ✅، انتخاب همه / هیچکدام، صفحه‌بندی)
2. رنیم یکی‌یکی (یا رد کردن با همان اسم قبلی)
3. اسم کلی برای اشتراک جدید
4. **انتخاب تاریخ انقضا**: بدون انقضا / ۷ / ۳۰ / ۹۰ / ۱۸۰ روز
5. دریافت لینک عمومی:
   ```
   https://your-app.up.railway.app/sub/TOKEN
   ```

این لینک را مستقیم در کلاینت‌ها (v2rayNG، Streisand، Hiddify، Clash و …) اضافه کن.

### پنل وب اشتراک
- اگر با **مرورگر** لینک را باز کنی → پنل HTML تاریک با کپی لینک، کپی محتوا، لیست کانفیگ‌ها
- اگر **کلاینت VPN** درخواست بدهد → محتوای خام base64
- پارامتر `?raw=1` همیشه خروجی خام می‌دهد
- اشتراک منقضی‌شده → وضعیت HTTP `410` و پیام مناسب

### مدیریت اشتراک‌های ساخته‌شده
- دکمه **🛠 اشتراک‌های من**
- لیست، جزئیات (لینک + انقضا + تعداد کانفیگ)
- حذف با تأیید

## منوی ربات

بعد از `/start`:

| دکمه | کار |
|------|-----|
| ➕ افزودن اشتراک | ذخیره لینک جدید |
| 🌐 ساخت از چند منبع | ساخت ساب از چند اشتراک با هم |
| 📋 لیست اشتراک‌ها | اشتراک‌های اصلی |
| 🛠 اشتراک‌های من | ساب‌های سفارشی ساخته‌شده |

داخل هر اشتراک اصلی:
- 📶 پینگ · 🧹 حذف مرده‌ها · 📤 خروجی · 🛠 ساخت سفارشی  
- 📝 یادداشت · 🔄 بروزرسانی · « بازگشت · 🗑 حذف

## ساختار پروژه

```
eshkhoshbakht/
├── bot.py              # هندلرهای تلگرام + سرور HTTP (aiohttp)
├── storage.py          # SQLite (subs + generated_subs)
├── config_parser.py    # پارس/رنیم/encode ساب
├── pinger.py           # پینگ TCP موازی
├── requirements.txt
├── Dockerfile
├── .env.example
└── README.md
```

### دیتابیس
- `subs` — اشتراک‌های اصلی کاربر (`updated_at` برای زمان آخرین بروزرسانی)
- `generated_subs` — ساب‌های سفارشی (`token`, `configs`, `created_at`, `expires_at`)

مهاجرت ستون‌های جدید (`updated_at`, `expires_at`) خودکار است.

## متغیرهای محیطی

| متغیر | الزامی | توضیح |
|-------|--------|--------|
| `BOT_TOKEN` | بله | توکن BotFather |
| `ADMIN_IDS` | توصیه‌شده | آیدی عددی تلگرام (با کاما جدا). خالی = همه دسترسی دارند |
| `BASE_URL` | بله برای لینک کامل | مثلاً `https://xxx.up.railway.app` بدون اسلش آخر |
| `DB_PATH` | خیر | پیش‌فرض `data/bot.db` |
| `PORT` | خیر | Railway خودش ست می‌کند (پیش‌فرض ۸۰۸۰) |

## دیپلوی روی Railway

1. ریپو را به GitHub پوش کن.
2. در Railway پروژه جدید بساز → **Deploy from GitHub repo**.
3. Variables را طبق جدول بالا ست کن (مخصوصاً `BASE_URL`).
4. یک **Volume** بساز و mount path را بگذار: `/app/data`  
   تا دیتابیس با هر دیپلوی پاک نشود.
5. Deploy بزن.

ربات همزمان:
- polling تلگرام را اجرا می‌کند
- روی پورت Railway سرور HTTP برای `/sub/{token}` و `/health` بالا می‌آورد

بررسی سلامت: `GET /health` → `ok`

## اجرای محلی (اختیاری)

```bash
python -m venv .venv
source .venv/bin/activate   # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt

export BOT_TOKEN=...
export ADMIN_IDS=123456789
export BASE_URL=http://localhost:8080
export PORT=8080

python bot.py
```

## وابستگی‌ها (`requirements.txt`)

- `aiogram` — ربات تلگرام
- `httpx` — دریافت لینک‌های اشتراک
- `aiohttp` — سرو HTTP سابسکریپشن و پنل وب

## نکات امنیتی

- حتماً `ADMIN_IDS` را ست کن تا فقط خودت (یا افراد مشخص) به ربات دسترسی داشته باشند.
- لینک‌های `/sub/TOKEN` **عمومی** هستند؛ هرکس لینک را داشته باشد کانفیگ‌ها را می‌بیند. فقط به افراد مورد اعتماد بده.
- برای انقضای خودکار از گزینه تاریخ انقضا هنگام ساخت استفاده کن.

## خلاصه تغییرات نسبت به نسخه اولیه

1. دکمه‌ای شدن خروجی ساب، آخرین بروزرسانی، حذف گروهی کانفیگ‌های مرده  
2. ساخت اشتراک سفارشی با انتخاب و رنیم کانفیگ‌ها  
3. سرو لینک روی دامنه Railway + پنل HTML در مرورگر  
4. لیست و حذف اشتراک‌های ساخته‌شده  
5. **تاریخ انقضا** برای ساب سفارشی (بدون انقضا / ۷ تا ۱۸۰ روز)  
6. **ساخت از چند منبع** — انتخاب چند اشتراک و ترکیب کانفیگ‌ها در یک ساب جدید  
7. هدر `subscription-userinfo` با فیلد `expire` برای کلاینت‌ها
