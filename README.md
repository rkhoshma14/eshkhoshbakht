# ربات رنیم کانفیگ اشتراک

یه لینک اشتراک (subscription) بهش میدی، کانفیگ‌هاشو پارس می‌کنه، لیستشونو نشون میده و
با هر اسمی که بخوای کانفیگ انتخابی رو برات برمی‌گردونه.

پشتیبانی از فرمت‌های: `vmess`, `vless`, `trojan`, `ss`, و هر فرمت دیگه‌ای که بعد از
`#` اسم (remark) داشته باشه.

## استفاده

با `/start` یه منوی دکمه‌ای (Reply Keyboard) نشون داده میشه:

- **➕ افزودن اشتراک** — ازت لینک اشتراک رو می‌پرسه و جایگزین لینک قبلی می‌کنه
- **📋 لیست کانفیگ‌ها** — لیست کانفیگ‌ها رو با دکمه شیشه‌ای (Inline) نشون میده
- **🔄 بروزرسانی** — دوباره از روی همون لینک، کانفیگ‌هارو بروز می‌کنه

بعد از زدن روی یک کانفیگ از لیست، ربات ازت اسم جدید رو می‌پرسه و کانفیگ رنیم‌شده رو
به صورت متن (قابل کپی) برات می‌فرسته.

## دیپلوی روی Railway

1. این پوشه رو به یک ریپازیتوری گیت‌هاب پوش کن.
2. توی Railway یک پروژه جدید بساز و از گزینه **Deploy from GitHub repo** همین ریپو رو انتخاب کن.
   Railway به خاطر وجود `Dockerfile` خودش تشخیص میده و بیلد می‌کنه.
3. توی تب **Variables** این متغیرها رو ست کن:
   - `BOT_TOKEN` — توکنی که از BotFather گرفتی
   - `ADMIN_IDS` — آیدی عددی تلگرام خودت (با کاما جدا کن اگه چندتا ادمین داری). اگه خالی
     بذاری همه می‌تونن از ربات استفاده کنن، پس حتما پرش کن.
   - `DB_PATH` — اختیاری، پیش‌فرض `data/bot.db`
4. یک **Volume** بساز و mount path رو بذار `/app/data` (همون مسیری که `DB_PATH` توش
   ذخیره میشه). بدون این Volume، با هر دیپلوی جدید دیتابیس (لینک اشتراک ذخیره‌شده) پاک میشه —
   دقیقا مثل کاری که برای پایداری Marzban روی Railway انجام دادی.
5. Deploy بزن. ربات با polling کار می‌کنه، پس نیازی به دامنه یا پورت باز نیست.

## نکته امنیتی

حتما `ADMIN_IDS` رو ست کن تا فقط خودت بتونی از ربات استفاده کنی، چون هرکسی که به
ربات پیام بده می‌تونه لینک اشتراک بذاره و کانفیگ‌هاشو ببینه.
