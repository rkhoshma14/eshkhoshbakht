# ربات رنیم کانفیگ اشتراک

چند تا لینک اشتراک (subscription) بهش میدی، هرکدوم رو با یه اسم و یادداشت دلخواه
ذخیره می‌کنه، کانفیگ‌های داخلشونو پارس می‌کنه، و با هر اسمی که بخوای کانفیگ انتخابی
رو برات برمی‌گردونه.

پشتیبانی از فرمت‌های: `vmess`, `vless`, `trojan`, `ss`, و هر فرمت دیگه‌ای که بعد از
`#` اسم (remark) داشته باشه.

## استفاده

با `/start` یه منوی دکمه‌ای (Reply Keyboard) نشون داده میشه:

- **➕ افزودن اشتراک** — لینک رو می‌پرسه، بعد یه اسم (مثلا «آمریکا - محمد») و در آخر
  یه یادداشت اختیاری (یا زدن دکمه «بدون یادداشت»)
- **📋 لیست اشتراک‌ها** — لیست همه‌ی اشتراک‌های ذخیره‌شده رو نشون میده (هرکدوم با اسم
  و تعداد کانفیگ). روی هرکدوم بزنی، اسم و یادداشتش بالای صفحه نشون داده میشه و بعدش
  لیست کانفیگ‌های همون اشتراک با دکمه میاد. هرکدوم رو بزنی اسم جدید ازت پرسیده میشه
  و کانفیگ رنیم‌شده به صورت متن قابل کپی برمی‌گرده. توی همین صفحه این دکمه‌ها هم هست:
  - **📶 پینگ کانفیگ‌ها** — به همه‌ی کانفیگ‌های اون اشتراک به صورت موازی وصل میشه
    (TCP connect به آدرس و پورت هرکدوم) و نتیجه رو به میلی‌ثانیه، مرتب‌شده از سریع‌ترین
    به کندترین، برمی‌گردونه. کانفیگ‌هایی که وصل نشن «❌ تایم‌اوت» نشون داده میشن.
    توجه: این فقط سرعتِ برقراری اتصال TCP رو می‌سنجه، نه سرعت واقعی دانلود/آپلود از
    پشتِ VPN.
  - **📝 یادداشت** — هروقت بخوای می‌تونی یادداشت جدید برای اون اشتراک بفرستی؛ به
    یادداشت قبلی اضافه میشه، پاکش نمی‌کنه. اگه خواستی کاملاً پاک بشه، دکمه‌ی
    «🗑 حذف کامل یادداشت» رو بزن.
  - **🔄 بروزرسانی** — دوباره از روی لینک همون اشتراک، کانفیگ‌ها رو بروز می‌کنه
  - **« بازگشت به اشتراک‌ها**
  - **🗑 حذف اشتراک** — با یه پیام تأییدیه (برای جلوگیری از حذف تصادفی)، کل اشتراک
    و کانفیگ‌هاشو حذف می‌کنه.

## دیپلوی روی Railway

1. این پوشه رو به یک ریپازیتوری گیت‌هاب پوش کن.
2. توی Railway یک پروژه جدید بساز و از گزینه **Deploy from GitHub repo** همین ریپو رو انتخاب کن.
   Railway به خاطر وجود `Dockerfile` خودش تشخیص میده و بیلد می‌کنه.
3. توی تب **Variables** این متغیرها رو ست کن:
   - `BOT_TOKEN` — توکنی که از BotFather گرفتی
   - `ADMIN_IDS` — آیدی عددی تلگرام خودت (با کاما جدا کن اگه چندتا ادمین داری). **این
     متغیر اجباریه** — هم برای محدود کردن دسترسی به ربات، هم برای فعال شدن پنل وب
     (بدون `ADMIN_IDS`، پنل کلاً غیرفعال می‌مونه و هرکسی نمی‌تونه واردش بشه).
   - `DB_PATH` — اختیاری، پیش‌فرض `data/bot.db`
   - `BASE_URL` — دامنه‌ی عمومی سرویس (مثلا `https://your-app.up.railway.app`)، هم برای
     لینک اشتراک‌های سفارشی هم برای پنل وب لازمه.
4. یک **Volume** بساز و mount path رو بذار `/app/data` (همون مسیری که `DB_PATH` توش
   ذخیره میشه). بدون این Volume، با هر دیپلوی جدید دیتابیس پاک میشه.
5. از تب **Settings → Networking** یه **Public Domain** فعال کن (چون سرویس الان یه
   وب‌سرور واقعی هم داره: لینک‌های اشتراک عمومی + پنل وب). آدرسی که Railway بهت میده
   رو تو `BASE_URL` بذار.
6. Deploy بزن.

## پنل وب

علاوه بر ربات تلگرام، یه پنل وب کامل هم هست که همون کارهای ربات رو با کیبورد و ماوس
انجام میده — آدرسش `BASE_URL/panel`.

### راه‌اندازی (یک‌بار، اجباری)

Telegram Login Widget (روش لاگین پنل) فقط روی دامنه‌ای کار می‌کنه که به ربات معرفی
کرده باشی:

1. تو تلگرام به [@BotFather](https://t.me/BotFather) پیام بده.
2. `/setdomain` رو بفرست، ربات مورد نظر (خوشبخت) رو انتخاب کن.
3. دامنه‌ی همون `BASE_URL` که تو Railway ست کردی رو بفرست (بدون `https://`، فقط مثل
   `your-app.up.railway.app`).
4. مطمئن شو `ADMIN_IDS` تو Railway ست شده — وگرنه پنل کلاً قفل می‌مونه.

### استفاده

با ورود به `BASE_URL/panel` یه دکمه‌ی «ورود با تلگرام» می‌بینی. بعد از لاگین
(که فقط برای آیدی‌های داخل `ADMIN_IDS` موفق میشه)، وارد پنل میشی:

- **📋 اشتراک‌ها** — افزودن، مشاهده‌ی لیست کانفیگ‌ها، پینگ، حذف کانفیگ‌های مرده،
  خروجی گرفتن، ویرایش یادداشت، بروزرسانی و حذف — همه از یه صفحه.
- هر کانفیگ یه چک‌باکس داره؛ هرچقدر که بخوای (حتی از چند اشتراک مختلف با هم) تیک بزن،
  از پایین صفحه دکمه‌ی **🛠 ساخت اشتراک سفارشی** میاد، برای هرکدوم اسم دلخواه بذار،
  یه اسم کلی و تاریخ انقضا انتخاب کن — یه لینک اشتراک عمومی جدید ساخته میشه.
- **🛠 اشتراک‌های سفارشی من** — لیست همه‌ی اشتراک‌های سفارشی‌ای که ساختی، با لینک و
  وضعیت انقضا، قابل حذف.

سشن لاگین ۳۰ روزه است و فقط تو حافظه‌ی سرویس نگه داشته میشه؛ اگه سرویس ری‌استارت بشه
باید دوباره لاگین کنی (دیتای اشتراک‌ها البته دست‌نخورده می‌مونه، چون تو دیتابیسه).

## نکته امنیتی

حتما `ADMIN_IDS` رو ست کن — هم برای محدود کردن دسترسی به ربات، هم چون پنل وب بدونش
کلاً غیرفعال می‌مونه (امنیت پیش‌فرض).
